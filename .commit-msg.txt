Wire PNG decode through WebCodecs — hardware image decode via main→renderer bridge

WebCodecs ImageDecoder only exists in the renderer, but PNG decoding
for DEM Terrarium tiles and GIBS NDVI canopy tiles happens in the main
process (pngjs pure JS decode).

Add image decode bridge:
  Main process sends raw PNG bytes → renderer decodes with WebCodecs
  → sends back RGBA pixel data → main process extracts elevation/NDVI

Flow:
  dem-tiles.ts / canopy-service.ts
    → decodeImageViaRenderer(bytes, 'image/png')
    → webContents.send('image:decode-request', { id, bytes })
    → renderer: webCodecs.decodeImageFromBytes(bytes)
    → ipcRenderer.send('image:decode-response', { id, data })
    → main: resolves promise with decoded pixels
  Falls back to pngjs if bridge unavailable or times out (5s).

Files:
  src/main/services/image-decode-bridge.ts — main-side bridge
  src/renderer/globe/hal/webcodecs.ts — decodeImageFromBytes method
  src/renderer/globe/hal/index.ts — wire decode-request listener
  src/main/services/dem-tiles.ts — try WebCodecs first, pngjs fallback
  src/main/services/canopy-service.ts — try WebCodecs first, pngjs fallback
