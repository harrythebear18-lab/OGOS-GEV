Add WASM SIMD compute backend — f32x4 vector kernels

Real WebAssembly SIMD module compiled from WAT source, wired into
the compute dispatcher as a backend between WebGPU and CPU worker.

Kernels (4):
  band_math   — (A - B) / (A + B)  [NDVI, NDWI, NBR]  (f32x4 SIMD)
  slope       — Horn's method, gradient magnitude     (scalar f32)
  hillshade   — slope + aspect → shading               (scalar f32)
  box_blur    — 3x3 box filter [anomaly detection]    (scalar f32)

The band_math kernel uses v128.load / v128.store and f32x4
arithmetic to process 4 floats per iteration. The slope and
hillshade kernels use scalar f32 (3x3 neighborhood makes SIMD
loads impractical) but still benefit from WASM's native execution
and avoid JS engine overhead.

Hillshade trig strategy: WASM has no sin/cos/atan. Instead, the 4
sun constants (cos_zenith, sin_zenith, cos_azimuth, sin_azimuth)
are precomputed in JS and passed as f32 parameters. Per-pixel
cos(slope), sin(slope), cos(aspect), sin(aspect) are computed
algebraically:
  cos(atan(x)) = 1/sqrt(1+x²)
  sin(atan(x)) = x/sqrt(1+x²)
  cos(aspect) = -dzdx/r, sin(aspect) = dzdy/r

Build pipeline:
  scripts/compile-wasm.mjs — WAT → WASM via wabt
  npm run compile:wasm — standalone compile
  npm run build — compile:wasm runs before electron-vite build
  simd-kernels.wasm (1514 bytes) served from public/ at runtime

Dispatcher routing (priority order):
  1. WebGPU (if available + grid large enough)
  2. WASM SIMD (if SIMD-eligible task: ndvi, ndwi, nbr, slope, hillshade, anomaly)
  3. CPU worker pool (worker_threads via IPC)
  4. No-op (return empty)
